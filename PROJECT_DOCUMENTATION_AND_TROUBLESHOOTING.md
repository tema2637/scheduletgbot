# Документация и ретроспектива проекта: Telegram-бот расписания («Опять пары»)

В данном документе зафиксирована полная история развития проекта, исходное состояние, добавленные функции, архитектурные решения, возникшие проблемы и способы их устранения, а также регламенты и инструкции на будущее.

---

## 1. Исходное состояние проекта

### Архитектура и стек
* **Язык и фреймворк**: Python 3.12, `aiogram` 3.20–3.25.
* **База данных**: SQLite (`users.db`), хранящая только `(user_id, group_name)`.
* **Источник данных**: локальный Excel-файл расписания (`imports/Расписание-2.xlsx`), конвертируемый скриптом `schedule_parser.py` в единый `data/schedule.json`.
* **Серверное окружение**: Docker-контейнер Alpine Linux (доступ по SSH), Python-окружение `/config/venv/bin/python`.
* **Запуск**: shell-скрипт `start_bot.sh`.

### Проблемы исходной версии
1. **Сдвиг звонков в понедельник**: расписание колледжа изменило время второй пары по понедельникам (с 10:10 на 11:25), однако константы времени были рассинхронизированы между парсером и модулями отображения.
2. **Потеря занятий в парсере (1502 записи)**: парсер пропускал часть пар (например, занятия по БЖ у групп ИКС 243/244).
3. **Объединение нескольких пар в одной ячейке**: если в одной ячейке таблицы было записано 2–3 разных предмета для разных недель (например, спецкурс + общая энергетика + физкультура), парсер склеивал их в одно некорректное имя или терял часть недель.
4. **Бесконечный лог-файл**: `bot.log` рос без ограничений (накопился до 2.5 МБ на проде).
5. **Отсутствие изоляции процессов**: не было проверки блокировки процесса, запуск второго экземпляра приводил к `TelegramConflictError`.
6. **Заспамливание Telegram API проверками подписки**: каждый клик и сообщение заново запрашивали статус членства в канале через `get_chat_member`.

## 2. Что было добавлено и улучшено

### 2.1. Исправление ядра и данных (1521 запись)
* **Модуль `times.py`**: вынесен в единый источник истины для дней недели и звонков (`TIME_SLOTS`), исключив расхождения между парсером, валидацией и ботом.
* **Парсер многопредметных ячеек (`_lesson_units` в `schedule_parser.py`)**:
  * Введён алгоритм деления текстового блока перед преподавателем по скобкам недель `RE_WEEKS_PAREN`.
  * Реализовано наследование аудитории внутри блока.
  * Исправлен regex преподавателей (`RE_TEACHER_FULL`), добавлена поддержка инициалов без точек (`Кожина Е Н.`, `Шишкина Е Б.`).
  * Для одиночных занятий сохранена исходная логика извлечения, сохранившая маркеры подгрупп (`Срокина/302`).
  * Число валидных записей расписания выросло с **1502** до **1521** (0 ошибок валидации).

### 2.2. Защита процессов и отказоустойчивость
* **`flock` на уровне shell**: запуск бота через `flock -n .bot.lock` предотвращает запуск двух параллельных экземпляров на одном токене.
* **Ротация логов**: внедрён `RotatingFileHandler` (до 5 файлов по 5 МБ).
* **Кэширование проверок подписки**: TTL 300с для подписанных, 30с для отрицательных ответов.
* **Изолированный тестовый бот**: развёрнут отдельный стенд `/config/schedule_bot_test` с отдельной БД `users_test.db` и ботом `@Ollamamonitorbbot` для безопасной обкатки до выката на прод.

### 2.3. Поиск преподавателей и режим преподавателя
* Индексация 59 преподавателей с канонизацией инициалов.
* Поиск по фамилии: прямо из чата (текстом), по кнопке `🔍 Преподаватель` или по команде `/t Фамилия`.
* В `⚙️ Настройки` добавлен выбор роли: «Я студент (выбрать группу)» / «Я преподаватель (выбрать ФИО)». В режиме преподавателя расписание показывает закреплённые группы.

### 2.4. Настраиваемые напоминания
* Выбор времени в меню настроек:
  * Вечерние слоты (`18:00`, `19:00`, `20:00`, `21:00`, `22:00`) — присылают пары на **завтра**.
  * Утренние слоты (`07:00`, `07:30`, `08:00`) — присылают пары на **сегодня**.
  * Кнопка отключения напоминаний.
* Фоновый асинхронный воркер без внешних зависимостей.

### 2.5. Автооповещения об изменении расписания
* Фоновая проверка файла `schedule.json` по mtime и SHA-256 каждые 30 секунд.
* Интеллектуальный дифф: рассылка отправляется **только тем пользователям и группам**, у которых реально изменился состав или время пар.

### 2.6. Генерация расписания картинкой (Pillow)
* Модуль `image_generator.py`: рендерит темную стильную PNG-карточку (1080px):
  * Неделя (`render_week_image`): команда `/pic` или инлайн-кнопка под текстом недели.
  * День (`render_day_image`): команда `/daypic` или инлайн-кнопка под текстом дня.
* В репозиторий встроены шрифты `DejaVuSans` и `DejaVuSans-Bold` в директорию `assets/`.

### 2.7. Работа в беседах групп
* Бота можно добавить в чат/беседу группы.
* Настройка группы чата: команда `/group ИМЯ_ГРУППЫ` (например `/group РЗ 252`).
* Доступны команды: `/today`, `/tomorrow`, `/week`, `/pic`, `/daypic`.
* Middleware проверки подписки на канал автоматически пропускает запросы из групповых чатов (`chat.type in ('group', 'supergroup')`).

### 2.8. Статистика для администратора
* Команда `/stats` (доступна только `ADMIN_ID`):
  * Количество пользователей в ЛС и количество бесед.
  * Активные пользователи за 24 часа и 7 дней.
  * Количество включённых напоминаний.
  * Количество пользователей в режиме преподавателя.
  * Топ-5 популярных групп.

## 3. Ошибки, с которыми сталкивались, и их решения

### Ошибка 1. Исчезновение пятничной пары у группы РЗ 252
* **Симптом**: пользователь сообщил, что в пятницу на 2-й паре у РЗ 252 пусто, хотя в Excel стоят занятия.
* **Причина**: исходная ячейка содержала 3 предмета:
  ```text
  311 ПКП в ПД (1-8,12,15,17)
  311 Общ.энерг.(14,16) Шаталов Н.А.
  Физ.кул.(9-11,13) Кобзев
  ```
  Парсер собирал весь текст до преподавателя Шаталова в одно имя: `ПКП в ПД (1-8...) 311 Общ.энерг.` с неделями `[14, 16]`. Занятия с 1 по 8 неделю полностью терялись.
* **Решение**: написан парсер `_lesson_units`, который внутри одного учительского блока находит все скобки `(недели)` и нарезает каждую пару отдельно, присваивая ей корректный предмет, кабинет и преподавателя.

### Ошибка 2. Преподаватели без точек в инициалах
* **Симптом**: преподаватель `Кожина Е Н.` не определялась как преподаватель, её фамилия попадала в название предмета, а поле `TeacherName` оставалось пустым.
* **Причина**: регулярное выражение `RE_TEACHER_FULL` требовало обязательную точку после первого инициала `[А-ЯЁ]\.`.
* **Решение**: обновлено регулярное выражение:
  ```python
  RE_TEACHER_FULL = re.compile(
      r'[А-ЯЁ][а-яё]+(?:-[А-ЯЁ][а-яё]+)?\s+'
      r'(?:[А-ЯЁ]\.\s?[А-ЯЁ]?\.?|[А-ЯЁ]\s+[А-ЯЁ]\.)'
  )
  ```

### Ошибка 3. Экспорт календаря (.ics) и лимит клиентов в 200 событий
* **Симптом**: календарь для РЗ 252 показывал Пн–Ср, а Чт и Пт пропадали.
* **Причина**: в семестре 309 событий. Почтовые клиенты и мобильные календари (Apple Calendar, Google, Samsung) при импорте `.ics` обрезают файл ровно на 200 событиях. Так как пары генерировались по группам предметов, первые 200 событий заняли первые дни недели.
* **Решение**: введена сортировка событий строго по хронологии и меню выбора периода (1, 2, 4 недели). Однако из-за сложности удаления импортированных событий со стороны пользователей фича была полностью удалена по просьбе заказчика.

### Ошибка 4. Квадраты вместо русских букв на картинках расписания
* **Симптом**: сгенерированные Pillow картинки отображали прямоугольники с крестами (`[]`) вместо букв.
* **Причина**: в минималистичном Alpine Linux отсутствуют системные шрифты с кириллицей, а `ImageFont.load_default()` не содержал глифов кириллицы.
* **Решение**: шрифты `DejaVuSans.ttf` и `DejaVuSans-Bold.ttf` добавлены напрямую в проект в папку `assets/`. В коде реализована безопасная загрузка через `ImageFont.truetype()`.

### Ошибка 5. Наложение текста в картинке одного дня (`render_day_image`)
* **Симптом**: время пары налезало на длинное название предмета.
* **Причина**: использовались фиксированные смещения X без учёта ширины текста времени и длинных названий предметов.
* **Решение**: внедрена чёткая трёхколоночная вёрстка: колонка времени (`PAD + 25px..285px`), предмет по центру, данные о преподавателе и кабинете прижаты к правому краю. Добавлена функция `fit_text()`, обрезающая слишком длинные названия с добавлением троеточия `…`.

### Ошибка 6. Блокировка Event Loop синхронным рендерингом Pillow
* **Симптом**: риск зависания бота при одновременных запросах картинок несколькими десятками пользователей.
* **Причина**: Pillow — CPU-bound синхронная библиотека.
* **Решение**:
  1. Вызовы рендеринга перенесены в отдельный поток: `await asyncio.to_thread(render_week_image, ...)`.
  2. Внедрён in-memory LRU-кэш (`OrderedDict` на 128 записей) с ключом, включающим хэш ревизии расписания. Повторные запросы отдаются за <1 мс без расчёта пикселей.

### Ошибка 7. Миграция базы данных SQLite в Alpine Linux
* **Симптом**: ошибка `sqlite3.OperationalError: Cannot add a column with non-constant default` при попытке выполнить:
  ```sql
  ALTER TABLE user_preferences ADD COLUMN last_active TIMESTAMP DEFAULT CURRENT_TIMESTAMP;
  ```
* **Причина**: версия SQLite в окружении не поддерживает динамические функции по умолчанию (`CURRENT_TIMESTAMP`) в операции `ALTER TABLE ADD COLUMN`.
* **Решение**: разделено на два шага:
  ```python
  c.execute('ALTER TABLE user_preferences ADD COLUMN last_active TIMESTAMP DEFAULT NULL')
  c.execute('UPDATE user_preferences SET last_active=CURRENT_TIMESTAMP WHERE last_active IS NULL')
  ```

### Ошибка 8. FloodWait и BotBlocked при рассылках
* **Симптом**: если пользователь заблокировал бота, цикл рассылки мог падать или зависать на лимитах.
* **Решение**:
  * Перехват `TelegramForbiddenError`: у заблокировавшего пользователя автоматически сбрасывается флаг напоминания в БД.
  * Перехват `TelegramRetryAfter`: бот выдерживает точную паузу `exc.retry_after` и повторяет отправку.

### Ошибка 9. Пропадание партнерской ссылки EtherVPN
* **Симптом**: исчез рекламный футер под расписанием.
* **Причина**: ссылка ранее была захардкожена в шаблоны, а при рефакторинге вынесена в переменные окружения `FOOTER_TEXT` и `FOOTER_URL`, которые не были прописаны на сервере.
* **Решение**: установлены штатные дефолтные значения прямо в `config.py`:
  * `FOOTER_TEXT`: `Лучший VPN — EtherVPN`
  * `FOOTER_URL`: `https://t.me/ethervpnbot?start=partner_268964754`

### Ошибка 10. Сбой SSH-доступа к контейнеру
* **Симптом**: `paramiko.ssh_exception.SSHException: Error reading SSH protocol banner`, соединение сбрасывается (`Connection closed by remote host`).
* **Причина**: упал внутренний процесс контейнера или sshd внутри контейнера. Хостовая машина работает, но проброс SSH-порта в контейнер не отдаёт баннер.
* **Решение**: перезапуск Docker-контейнера через команду на хосте `docker restart <имя_контейнера>` или через панель управления хостингом.

## 4. Инструкция для администратора и разработчика на будущее

### 4.1. Обновление расписания из нового Excel
1. Загрузить новый файл `Расписание-*.xlsx` в `imports/`.
2. Запустить локальную проверку:
   ```bash
   python schedule_parser.py "imports/Новое_Расписание.xlsx" --check
   ```
3. Если ошибок нет, опубликовать в `data/schedule.json`:
   ```bash
   python schedule_parser.py "imports/Новое_Расписание.xlsx" --output data/schedule.json --report data/last_import_report.json
   ```
4. Запустить тесты:
   ```bash
   python -m unittest discover -s tests -v
   ```
5. Загрузить новый `data/schedule.json` на сервер в папку `/config/schedule_bot/schedule.json`.
6. **Перезапуск бота не требуется**: бот автоматически обнаружит изменение файла в течение 30 секунд, обновит кэш в памяти и разошлёт оповещения тем группам, у кого изменились пары.

### 4.2. Управление ботом на сервере
* **Директория прода**: `/config/schedule_bot`
* **Проверка статуса процесса**:
  ```bash
  ps -ef | grep -E "python.*main.py|flock" | grep -v grep
  ```
* **Просмотр логов**:
  ```bash
  tail -f /config/schedule_bot/bot.log
  ```
* **Штатный перезапуск бота**:
  ```bash
  pkill -f '/config/schedule_bot/main.py' || true
  sleep 2
  cd /config/schedule_bot && nohup ./start_bot.sh </dev/null > bot_stdout.log 2>&1 &
  ```

### 4.3. Резервные копии
* Резервные копии базы данных создаются перед любыми массовыми операциями командой:
  ```bash
  cp -p /config/schedule_bot/users.db /config/schedule_bot/users.db.bak_$(date +%Y%m%d_%H%M%S)
  ```
* Полный архив прода сохранён в: `/config/schedule_bot_backup_20261102_162214.tar.gz`.
